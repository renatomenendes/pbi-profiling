# pbi-profiling v1.0.1

Packaging hotfix for the Windows portable release.

## Fixed

The v1.0.0 ZIP contained an additional top-level directory inside the archive. With the standard Windows **Extract All** flow, Windows created an outer destination folder and the archive created a second folder with the same name:

```text
pbi-profiling-v1.0.0-windows-portable\
└── pbi-profiling-v1.0.0-windows-portable\
    └── pbi-profiling.cmd
```

v1.0.1 removes that redundant archive directory.

After downloading and using the standard Windows **Extract All** command, the expected layout is now:

```text
C:\projetos\
└── pbi-profiling-v1.0.1-windows-portable\
    ├── pbi-profiling.cmd
    ├── src\
    ├── docs\
    ├── schemas\
    └── vendor\
```

The launcher is therefore available directly at:

```powershell
C:\projetos\pbi-profiling-v1.0.1-windows-portable\pbi-profiling.cmd
```

## Validation

The release pipeline now simulates the standard Windows extraction destination and verifies that:

- `pbi-profiling.cmd` exists directly in the extracted folder;
- `src/app.js` exists directly below that folder;
- no second nested package directory exists;
- the unpacked runtime successfully profiles a synthetic PBIP;
- `profile.html`, `profile.json` and `profile.rag.jsonl` are produced.

## Scope

This release changes packaging only.

There are no changes to:

- the profiling engine;
- PBIP validation;
- PBIX open workflow;
- TMDL/PBIR parsing;
- DAX or Power Query/M analysis;
- HTML runbook generation;
- JSON/RAG contracts;
- business-context or analytical-opportunity logic.

## Requirements

- Windows 10 or 11;
- Node.js 20 or newer;
- Power BI Desktop only for the optional PBIX-open workflow.

No administrator rights, `npm install`, Python installation or PowerShell ExecutionPolicy change is required.
